# TrekUI

A suite of four Android apps (a home-screen launcher, an SMS/MMS app, a keyboard and a lock-screen wake screen), written in pure Java and drawn entirely in code on a Canvas, in the same set of starship-console interfaces.

**Version 44** · [Project site](https://gungreeneyes.github.io/TrekUI.Java/) · [Privacy policy](https://gungreeneyes.github.io/TrekUI.Java/privacy.html) ([PRIVACY.md](PRIVACY.md)) · [Releases](https://github.com/GunGreenEyes/TrekUI.Java/releases) · [Changelog](CHANGELOG.md)

> **Original work.** TrekUI is an independent design: every frame, glyph, font and synthesized sound is drawn or generated by this project. No third-party recordings or artwork ship with the apps.

## The four apps

All four share one `:core` library (look, fonts, sounds, licensing, the suite contract), one version number and one signing key. Each works on its own; installed together, the companions follow the launcher's interface and sub-theme.

| App | Module | Package (develop build) | What it is |
|---|---|---|---|
| **TrekUI Launcher** | `:app` | `com.gungreeneyes.trekui` (`…trekui.dev`) | A full home-screen launcher: home, app drawer, search, pull-down shade, dialer, live panels, widgets and start-up sequences, in five interfaces with sub-themes. |
| **TrekUI Messages** | `:messages` | `com.gungreeneyes.trekui.messages` (`….messages.dev`) | A complete default SMS/MMS app: conversations, picture messages, search, drafts, blocking, dual SIM, notifications with inline reply. |
| **TrekUI Keyboard** | `:keyboard` | `com.gungreeneyes.trekui.keyboard` (`….keyboard.dev`) | An on-screen keyboard (input method) in four layouts, with no internet permission at all. |
| **TrekUI Lock Screen** | `:lockscreen` | `com.gungreeneyes.trekui.lockscreen` (`….lockscreen.dev`) | A wake screen shown over Android's lock screen. Unlocking always goes through Android's own PIN, pattern or biometric: it is a look, not a lock. |

The five interfaces, all starship consoles: COMMAND (11 colour themes), IMPERIAL (5), COLLECTIVE (5), CLASSIC CONSOLE and NEXT CONSOLE (3 each).

## Supported devices

**TrekUI works on every Android phone from 2022 onward, at every resolution and aspect ratio.** That includes:

- small phones and tall 20:9 / 21:9 phones;
- foldables, on both the inner and the outer screen;
- tablets in portrait and landscape;
- phones in landscape and in multi-window;
- large display-size and font settings.

The floor is much lower than that: `minSdk` is **26 (Android 8.0)** and `targetSdk` is **37**. Phones from 2022 shipped Android 11 to 13, so they are covered with room to spare. No screen hard-codes sizes or orientation: everything is sized from the window by `ScreenMetrics` (size classes, margins, columns, a UI scale clamped to 0.85–1.6), edge-to-edge, with status bar, navigation bar, display cutouts and keyboard insets handled on every API level.

## Install on a test device

### 1. Get the APKs

From a checkout, build everything into `dist/`:

```sh
./gradlew dist            # macOS / Linux / Git Bash
.\gradlew.bat dist        # Windows PowerShell
```

`dist/` then holds three files per app:

| App | For testers | Developer build | For Google Play |
|---|---|---|---|
| Launcher | `TrekUI-44-production-release.apk` | `TrekUI-44-develop-debug.apk` | `TrekUI-44-production-release.aab` |
| Messages | `TrekUI-Messages-44-production-release.apk` | `TrekUI-Messages-44-develop-debug.apk` | `TrekUI-Messages-44-production-release.aab` |
| Keyboard | `TrekUI-Keyboard-44-production-release.apk` | `TrekUI-Keyboard-44-develop-debug.apk` | `TrekUI-Keyboard-44-production-release.aab` |
| Lock Screen | `TrekUI-LockScreen-44-production-release.apk` | `TrekUI-LockScreen-44-develop-debug.apk` | `TrekUI-LockScreen-44-production-release.aab` |

`dist/` is not cleared between builds, so files from older versions may still be there: pick the `-44-` ones. Ready-built APKs are also attached to each [GitHub release](https://github.com/GunGreenEyes/TrekUI.Java/releases). The `.aab` files are for Play upload only; they cannot be installed directly.

Without a checkout, download the APKs from [GitHub Releases](https://github.com/GunGreenEyes/TrekUI.Java/releases), or the newest **Develop** run under [Actions](https://github.com/GunGreenEyes/TrekUI.Java/actions) (artifact `TrekUI-develop-debug-apk`; you must be signed in to GitHub).

### 2. Pick the right APK

- **`production-release`** is what testers should install. It is the store build: normal package names, 24-hour trial sessions, no test hooks.
- **`develop-debug`** installs **next to** it as a separate app ("TrekUI Dev", "TrekUI Messages Dev", and so on; package suffix `.dev`). It has 5-minute trial sessions and test hooks (in the launcher's purchase screen, long-press the header to simulate the purchase; debug intent extras are listed in [docs/MONETIZATION.md](docs/MONETIZATION.md#test-hooks)). The develop apps share the unlock with each other, not with the production apps.

### 3. Signing: what installs over what

A local build made without the upload key (no `signing/release.properties` or `TREKUI_*` variables) is signed with the shared debug key, release builds included. All four apps therefore carry the same signature, install side by side, and **share the unlock with each other** through the signature-protected suite provider.

Copies from Google Play are signed with Google's app signing key, so Android refuses to install one over the other (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`). To switch between a local build and a Play build, **uninstall first**. The layout is lost unless you export it first (launcher CONFIG › BACKUP › EXPORT LAYOUT) or Android backup restores it.

### 4. Install with adb

Turn on **Developer options › USB debugging** on the phone, connect it and accept the prompt. Then:

```powershell
# one app
adb install -r dist\TrekUI-44-production-release.apk

# all four (PowerShell)
Get-ChildItem dist\*-44-production-release.apk | ForEach-Object { adb install -r $_.FullName }
```

```sh
# all four (bash)
for f in dist/*-44-production-release.apk; do adb install -r "$f"; done
```

With several devices or emulators connected, list them with `adb devices` and target one with `-s`:

```sh
adb -s <serial> install -r dist/TrekUI-44-production-release.apk
```

For the develop builds, use `*-44-develop-debug.apk` in the same commands, or `./gradlew installDevelopDebug` to build and install straight from Gradle.

### 5. Or copy the APK to the phone

Copy the APK (USB, cloud drive, e-mail) and open it on the phone. If Android blocks it, allow **Install unknown apps** for the app you opened it from. On Samsung, if the install is refused outright, turn off **Settings › Security and privacy › Auto Blocker** for the moment.

On Android 13 and newer, an app installed from a file can have notification access and accessibility greyed out as a "restricted setting". If so, open **Settings › Apps › (the app) › ⋮ › Allow restricted settings**, then try again.

### 6. First-run setup

| App | What to do |
|---|---|
| **Launcher** | Open **TrekUI** and accept **SET AS DEFAULT HOME**, or choose it in **Settings › Apps › Default apps › Home app** (Samsung: **Settings › Apps › Choose default apps › Home app**). An eight-stop tour follows; replay it from CONFIG › DEFAULT HOME › REPLAY TOUR. |
| **Messages** | Open **TrekUI Messages** and accept the request to become the default SMS app (also offered by the SET DEFAULT key, the launcher's CONFIG › SUITE › MESSAGES, or **Settings › Apps › Default apps › SMS app**). |
| **Keyboard** | Open **TrekUI Keyboard**: STEP 1 enables it in Android's keyboard list, STEP 2 selects it in Android's keyboard picker, and a test field lets you try it. Android shows its standard warning when a keyboard is enabled; this one has no internet access. The launcher's CONFIG › SUITE › KEYBOARD opens the same picker. |
| **Lock Screen** | Open **TrekUI Lock Screen**, read the notification-access explanation and grant **notification access**; on Android 10+ also allow **Display over other apps** (without it, Android may block the wake screen and the normal lock screen shows instead). Use PREVIEW to check it, and the WAKE SCREEN switch, or the launcher's CONFIG › SUITE › LOCK SCREEN, to turn it on or off. |

### 7. Uninstall, or go back to the standard launcher

- **Standard launcher:** pick your previous home app in **Settings › Apps › Default apps › Home app** (Samsung: **Choose default apps › Home app**). Uninstalling TrekUI also hands home back to the system launcher.
- **Standard SMS app:** the launcher's CONFIG › SUITE › MESSAGES restores the previous one, or choose it in **Default apps › SMS app**.
- **Uninstall:** from the phone's app settings, or with adb:

```sh
adb uninstall com.gungreeneyes.trekui
adb uninstall com.gungreeneyes.trekui.messages
adb uninstall com.gungreeneyes.trekui.keyboard
adb uninstall com.gungreeneyes.trekui.lockscreen
# develop builds: the same names with .dev on the end, e.g. com.gungreeneyes.trekui.dev
```

### Other ways to install

- **BlueStacks (Windows/macOS):** use an instance running Android 9 (Pie 64-bit) or Android 11. Drag the APK onto the window, then set **Settings › Apps › Default apps › Home app › TrekUI**. For adb, enable **Settings › Advanced › Android Debug Bridge** and run `adb connect 127.0.0.1:<port>`; the `scripts/bluestacks.ps1` helper automates this.
- **Termux (build on the phone itself):** `bash scripts/setup.sh` installs JDK 21, the SDK and Termux's `aapt2`, then builds. See [docs/REMOTE_DEVELOPMENT.md](docs/REMOTE_DEVELOPMENT.md#4-building-on-the-phone-with-termux).
- **Google Play:** follow the link on the [project site](https://gungreeneyes.github.io/TrekUI.Java/) once the listings are live.

## Features

### TrekUI Launcher

Choose the interface in **CONFIG › INTERFACE** (family, then interface), and its colour theme from a preview strip. Every function works the same in all five interfaces; only geometry, lettering and colours change.

- **Home layouts:** a classic console frame, or press-to-deploy homes (COMMAND / CLASSIC / NEXT CONSOLE CASCADE, IMPERIAL TACTICAL DEPLOY, COLLECTIVE TRACE COLUMN or HUB AND SPOKE).
- **Launcher basics:** the full app list via `LauncherApps` (work profile and Secure Folder included), search, categories, hidden apps, uninstall, app shortcuts, clip-reveal launch animations.
- **Assignable everything:** long-press any tile, dock slot, elbow, bar segment, code block, title, clock or date to assign an app or launcher function, rename, recolour or give it a sound.
- **Live panels** (refreshing only while home is visible): chronometer with optional stardate, power, weather (Open-Meteo), calendar, media, ship systems, and up to 12 Android widget panels.
- **Console shade:** quick toggles, brightness and volume, and a notification log with inline REPLY and the apps' action keys. **Unread badges** on tiles and dock keys.
- **Console dialer:** keypad with contact matching, recents and contacts; emergency numbers always go through the system phone app.
- **CLOAK** (timed night mode) and **RED ALERT** (a pulsing alarm frame and looping sound, silent in Silent/Vibrate and Do Not Disturb), both also as Quick Settings tiles.
- **App groups, gestures and LOCK SCREEN:** OPEN GROUP unfolds up to 12 apps in the interface's style; double-tap, two-finger swipes, pinch and horizontal swipes can run any function; an optional lock function uses an accessibility service that reads nothing (Android 9+).
- **Layout safety:** CONFIG › BACKUP exports and imports the layout as JSON (credentials and location never exported), with automatic snapshots (newest 10) and UNDO LAST CHANGE.
- **Icons:** 109 original pictograms in every interface's style, ADW/Nova-compatible icon packs, and CHANGE ICON per app.
- **Smart devices:** Govee lights (LAN or cloud API with your key), Nest thermostats (your own Device Access project), Home Assistant (your own instance and token).
- **CONFIG › SUITE:** the active keyboard and picker, the wake screen switch, the default SMS app; companions that aren't installed get an INSTALL link.
- **Also:** first-run tour, six toy bridge stations (INFO › STATIONS, marked SIMULATION), a start-up sequence per interface, two widgets for other launchers, theming recipes for Samsung's Quick Panel, Signal, Chrome and the Samsung Keyboard.

### TrekUI Messages

- Default SMS/MMS app on Android 8.0+ (role request on 10+).
- Conversation list and threads with sent / delivered / not sent state; new messages to numbers or contacts; CALL, BLOCK, DELETE.
- MMS: up to 5 pictures through the system photo picker, group sends, incoming MMS downloaded at once.
- Search across names and message text, drafts per conversation, blocking (system list plus prefix rules), dual-SIM choice per conversation.
- Per-conversation notification channels with inline REPLY and MARK READ; quick replies from the incoming-call screen.
- Known limits are listed in [docs/MESSAGES.md](docs/MESSAGES.md#known-limits--follow-ups).

### TrekUI Keyboard

- Keys drawn in every interface and sub-theme.
- English QWERTY, German QWERTZ, French AZERTY and Spanish layouts (globe key or long-press space); two symbol pages, number and dial pads, a small emoji page.
- Shift and caps lock, long-press accents and digits, space-bar cursor, swipe left from DELETE to remove words; enter key labelled GO / SEARCH / SEND / NEXT / DONE.
- Up to three word completions (no autocorrect); nothing is learned in password or incognito fields.
- Synthesized key clicks, vibration, S–XL key heights per orientation, one-handed mode, number row.
- Typing never stops when a trial session ends; a small UNLOCK chip appears instead.

### TrekUI Lock Screen

- Big clock, date, an original decimal date (each year is 1000 units), next alarm, battery and charging, media controls.
- The notification list, never less private than Android's own lock screen (secret notifications never shown; private ones as the app name unless SHOW SENSITIVE CONTENT is on and Android allows it).
- CAMERA (the camera's secure mode) and TORCH.
- Swipe up or tap UNLOCK to hand over to Android's keyguard. No foreground service, accessibility service or device admin; an ended trial never blocks unlocking.

### Sounds

No recordings ship with any app. The launcher plays its own synthesized sounds; recordings can be added with **CONFIG › AUDIO SYSTEMS › DOWNLOAD SOUND LIBRARY** (fetched from public sources, checksum-verified, processed on the phone) or by importing your own files. See [docs/SOUNDS.md](docs/SOUNDS.md).

## Free to try, $0.99 to keep

- Every app is free, has **no ads and no subscriptions**, and every feature works from the first launch.
- Without a licence, each **trial session lasts 24 hours** (5 minutes in the develop flavor). When it ends, a purchase screen offers the one-time **$0.99 unlock** (`trekui_unlock`, Google Play in-app purchase), another session, or another home app. The launcher shows it only on its own home screen, never over another app; the keyboard and lock screen never block typing or unlocking.
- **One purchase in any of the four apps unlocks all of them.** It is permanent, restores on your other devices signed in to the same Google account, and works offline once granted.

Design and Play policy notes: [docs/MONETIZATION.md](docs/MONETIZATION.md).

## Permissions and privacy

None of the apps has analytics, ads, accounts or a developer server. Data stays on the device.

| App | Network use | Notable permissions |
|---|---|---|
| Launcher | Only what you turn on: weather (Open-Meteo), your Govee / Nest / Home Assistant devices, sound downloads, Google Play for the purchase | optional contacts, call log, calendar and approximate location; notification access (shade, media, badges) if you grant it; call phone |
| Messages | Google Play Billing only; message content stays in the system SMS/MMS store | SMS and MMS (default SMS handler), contacts (names), phone state (SIM list), notifications |
| Keyboard | **None**: `INTERNET` is removed from the manifest | the input-method binding and billing |
| Lock Screen | Google Play Billing only; notifications are held in memory while shown | notification access, optional "display over other apps" |

Details: [PRIVACY.md](PRIVACY.md) (the launcher's policy, also at the [project site](https://gungreeneyes.github.io/TrekUI.Java/privacy.html)), [docs/MESSAGES.md](docs/MESSAGES.md), [docs/KEYBOARD.md](docs/KEYBOARD.md#privacy), [docs/LOCKSCREEN.md](docs/LOCKSCREEN.md) and the Play declarations in [docs/PLAY_STORE.md](docs/PLAY_STORE.md).

## Build from source

You need **JDK 21**, the **Android SDK** (`platforms;android-37.0`, `build-tools;37.0.0`, `platform-tools`) and Git. The setup scripts install everything on a fresh machine and finish with a test build:

```sh
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1     # Windows; -WhatIf previews, -Emulators adds AVD images
bash scripts/setup.sh                                         # macOS / Linux / Termux; --dry-run, --emulators
```

Common tasks (on Windows use `gradlew.bat`):

```sh
./gradlew assembleDevelopDebug          # develop APKs, e.g. app/build/outputs/apk/develop/debug/
./gradlew installDevelopDebug           # install on the connected device or emulator
./gradlew assembleProductionRelease     # production APKs
./gradlew bundleProductionRelease       # production AABs
./gradlew dist                          # all of the above for all four apps, copied to dist/
./gradlew testDevelopDebugUnitTest      # JVM + Robolectric unit tests
./gradlew lintDevelopDebug              # lint
```

Prefix a task with a module to build one app, e.g. `./gradlew :messages:assembleDevelopDebug`.

| Flavor | Package | App name | Trial session |
|---|---|---|---|
| `develop` | `…` + `.dev` | "… Dev" | 5 minutes |
| `production` | `com.gungreeneyes.trekui[.messages/.keyboard/.lockscreen]` | TrekUI, TrekUI Messages, … | 24 hours |

Build types are `debug` (no shrinking) and `release` (R8, signed with the upload key from `signing/release.properties` or `TREKUI_*` variables, else the debug key). The version lives only in `version.properties`: one whole number for `versionName` and `versionCode` alike (this release **44**, the next **45**).

**Tests.** Unit tests (JVM and Robolectric), lint and the emulator matrix run in CI on every push. Locally, tests are run only when asked for (`./gradlew testDevelopDebugUnitTest`, or the emulator matrix above). See [docs/TESTING.md](docs/TESTING.md).

More: [docs/BUILD.md](docs/BUILD.md) (toolchain, flavors, signing, troubleshooting) and [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Releasing and staying current

- **Ship:** `scripts/release/ship.ps1` (Windows) or `scripts/release/ship.sh` bumps to the next whole number, writes the changelog and per-app Play notes, commits, tags `v<N>`, pushes and starts `release.yml`, which builds and signs all four apps, runs the full emulator matrix, creates the GitHub Release and uploads every app to the Play **internal** track. `-DryRun` / `--dry-run` shows the plan first. See [docs/RELEASE.md](docs/RELEASE.md).
- **One-time setup:** `scripts/release/setup-owner.ps1` creates the upload key and secrets, GitHub Pages and the weekly upgrade queue, and prints the Play Console checklist, which is written out in [docs/PLAY_STORE.md](docs/PLAY_STORE.md).
- **Staying current:** Dependabot, the weekly `platform-watch.yml` workflow and `scripts/maintenance/queue-upgrades.ps1` queue new Android API levels, Gradle and library updates as work items. See [docs/PLATFORM_UPDATES.md](docs/PLATFORM_UPDATES.md).
